# كلاي | اللعب مع بعض

نموذج أولي لمنصة ألعاب جماعية عبر الويب: شاشة مضيف تنشئ غرفة، وأجهزة الهاتف تنضم عبر QR وتعمل كوحدات تحكم مستقلة.

## التشغيل

```bash
npm install
npm run dev
```

افتح `http://localhost:3000/host.html` على شاشة المضيف. للانضمام من هاتف على الشبكة نفسها، عيّن `PUBLIC_BASE_URL` إلى عنوان المضيف الذي يمكن للهاتف الوصول إليه، مثل `http://192.168.1.20:3000`، ثم أعد تشغيل الخادم. اسمح بالاتصالات إلى المنفذ `3000` في جدار الحماية عند الحاجة. للاتصال عبر الإنترنت استخدم عنوان HTTPS عاماً.

يمكن تشغيل اختبارات إدارة الغرف باستخدام `npm test`.

## النشر على Render

يتضمن المستودع `render.yaml` كإعداد Blueprint. من لوحة Render اختر **New > Blueprint**، ثم اربط مستودع GitHub هذا واختر `main`. سيقرأ Render إعداد الخدمة، يثبت التبعيات، ويشغّل فحص الصحة على `/health`. يستخدم التطبيق `RENDER_EXTERNAL_URL` تلقائياً لبناء رابط HTTPS داخل رمز QR. يمكن تجاوز العنوان بتعيين `PUBLIC_BASE_URL` عند الحاجة.

### إعداد مكتبة الألعاب على Render

تحتاج ميزة حفظ الألعاب إلى إعداد متغيري البيئة `GAME_LIBRARY_GITHUB_TOKEN` و`GAME_LIBRARY_ADMIN_KEY` في Render، دون وضعهما في GitHub أو مشاركتهما في المحادثات. أنشئ Fine-grained personal access token محدوداً إلى مستودع `ah11026/klai` بصلاحية **Contents: Read and write**، وضعه في `GAME_LIBRARY_GITHUB_TOKEN`. أنشئ مفتاح إدارة قويّاً محلياً مثلاً بـ`openssl rand -hex 32` وضعه في `GAME_LIBRARY_ADMIN_KEY`. المستودع والفرع مضبوطَان افتراضياً على `ah11026/klai` و`main` ويمكن تغييرهما في `GAME_LIBRARY_REPOSITORY` و`GAME_LIBRARY_BRANCH`.

بعد إعادة نشر الخدمة، افتح «إضافة لعبة إلى المستودع» في شاشة المضيف وأدخل مفتاح الإدارة. يمكنك رفع ملف محلي أو استيراد مسار من مستودع GitHub عام بصيغة `owner/repository` مع الفرع والمسار، وإضافة معلومات الترخيص. يقتصر الحجم على 15 ميغابايت والامتدادات على ملفات الأنظمة المدعومة. يُضاف الملف والفهرس معاً إلى `public/games` في commit واحد؛ وبما أن المستودع عام، تصبح الملفات المحفوظة فيه قابلة للتنزيل علناً. تحقق بنفسك من حق إعادة توزيع كل لعبة ورخصتها قبل الرفع أو الاستيراد. اختر «تشغيل» بجانب لعبة محفوظة لفتحها في المحاكي.

### المحاكيات

تُشغّل صفحة `emulator.html` الألعاب عبر EmulatorJS من CDN الرسمي باستخدام النوى: `fceumm` (NES)، `snes9x` (SNES)، `mupen64plus_next` (N64)، و`pcsx_rearmed` (PS1). يتطلب التشغيل اتصالاً بالإنترنت لتحميل ملفات EmulatorJS. قد تحتاج بعض ألعاب PS1 إلى ملفات BIOS مناسبة. PS2 غير مدعوم في هذه الواجهة. تمرر وحدة التحكم أحداثها إلى لوحة مفاتيح المحاكي للاعب الأول؛ توجيه كل هاتف إلى لاعب مستقل يختلف حسب النواة ولم يكتمل بعد.

## ما يشمله النموذج

- إنشاء غرفة برمز من ستة أرقام ورمز QR.
- انضمام حتى أربعة لاعبين، مع إعادة استخدام المقاعد الشاغرة.
- إرسال ضغطات الأزرار وإفلاتها إلى المضيف عبر Socket.IO، وتحرير الأزرار عند انقطاع اللاعب.
- التحقق من رسائل الإدخال وتحديد معدلها، وحماية طلب QR برمز سري خاص بالمضيف.
- بث الأحداث إلى طبقة المحاكي عبر حدث المتصفح `remote-game-input`.

## حدود التكامل

تعمل الأنظمة NES وSNES وN64 وPS1 عبر EmulatorJS عند فتح اللعبة من المكتبة. يحتاج تحميل المحاكي إلى اتصال بالإنترنت، ولا يشمل المشروع ملفات ألعاب. تُرسل أزرار الهاتف حالياً إلى اللاعب الأول عبر لوحة مفاتيح المحاكي؛ فصل الهواتف على لاعبين مستقلين ودعم PS2 غير متاحين حالياً.

هذا نموذج أولي أحادي الخادم. قبل نشره للعامة أضف إدارة عمر الغرف، وتعامل إعادة الاتصال، ومراقبة إساءة الاستخدام، واستخدم HTTPS مع `PUBLIC_BASE_URL` موثوق.
